# srinishtha-api

Roda + Sequel API for the Srinishtha Technologies website (Neon Postgres). It also serves the
built site from `public/` with server-side SEO (per-page meta, JSON-LD, `sitemap.xml`, `robots.txt`, 301s).

## Local

```bash
cp .env.example .env        # fill DB_URL, JWT_SECRET
bundle install
bundle exec rake db:migrate
bundle exec rake db:seed    # website content; FORCE=1 also overwrites admin-edited projects/case studies
bundle exec rake admin:create EMAIL=you@srinishtha.com NAME="Your Name" PASSWORD='at-least-12-chars'
bundle exec puma -p 9292 config.ru
```

## Deploy on Render

1. Render → **New → Blueprint** → select this repo (uses `render.yaml` + `Dockerfile`).
2. Enter the secret env vars when prompted:
   - `DB_URL` – Neon connection string (`...?sslmode=require&channel_binding=require`)
   - `SITE_URL` – the public site, e.g. `https://srinishtha.vercel.app`
   - `CORS_ORIGINS` – same as `SITE_URL` (comma-separate several)
   `JWT_SECRET` is generated by Render.
3. Migrations already ran against Neon. For a fresh database run `bundle exec rake db:migrate db:seed` locally with that `DB_URL`.
4. Health check: `GET /api/version`.

**Uploads:** Render's free disk is wiped on every deploy, so images uploaded in the admin are lost.
Attach a Render Disk at `/app/uploads` (paid) or move uploads to S3 before relying on them.

## Frontend build (`public/`)

`public/` is the built React app, written there by `npm run build` in the frontend repo for local use.
It is git-ignored: in production the site is served by Vercel, and this API redirects page requests to `SITE_URL`.

## Security

Security headers + CSP, per-IP rate limits (login, password reset, contact form, uploads),
CORS restricted to `CORS_ORIGINS`, generic error messages in production, uploads verified by file signature,
password reset that never reveals whether an account exists.
